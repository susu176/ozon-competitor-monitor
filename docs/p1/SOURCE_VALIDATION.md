## 实际测试与证据

先请求公开站点的 robots.txt，检查采集政策，未直接抓取店铺列表：

```bash
curl --silent --show-error --max-time 25 --max-filesize 1048576 \
  --dump-header /tmp/ozon-p1-robots.headers \
  --output /tmp/ozon-p1-robots.body https://www.ozon.ru/robots.txt
```

实际返回：`curl: (56) CONNECT tunnel failed, response 403`。响应为代理 `HTTP/1.1 403 Forbidden`，`server: envoy`。HTTPS 隧道未建立，未获取 Ozon HTTP 响应，也未获取 robots.txt 正文。运行实例当前网络配置为 restricted，允许域名不包含 Ozon。综合配置及连接结果，确认本轮首先被环境出站网络限制阻断；不能把该响应归因于 Ozon 反爬、验证码、账号限制或店铺不存在。

证据：[结构化测试记录](evidence/2026-10-19-network-probe.json)、[代理响应头](evidence/2026-10-19-proxy-response.txt)。仅保留非敏感的诊断头，不保留凭据或 Cookie。

遇到共享主机级阻断后，没有重复请求同一地址，也没有继续发送两家店铺请求、分页请求、商品详情请求或猜测内部 API。未换域名绕过、关闭代理/TLS 验证、轮换 IP、使用登录 Cookie、调用付费服务或大规模抓取。

## 可行性结论

**当前云端网络条件下，免费公开页面路径无法开展验证。Ozon 数据源本身是否可用，尚不能判断；尚无证据支持稳定、合法、完整或每日可重复采集的结论。** GitHub Actions #6 的模拟流程成功也不能证明 Ozon 可访问，Actions runner 的网络出口与当前云实例不同。

未获取 robots 或使用条款，尚未完成访问许可检查。robots 允许也不等于获得接口授权；须结合公开规则及具体访问方式判断。没有真实产品样本，不开始推测性解析器、商品类目补全或真实自动监控开发。

## 已保存的最小环境配置及下一步

通过配置草稿工具保存新增域名 `www.ozon.ru` 和 `ozon.ru`，保留原有 package_managers 预设；没有开放通配符、API/图片 CDN、其他站点或凭据。保存结果 `status=saved`、`requires_publish=true`。**草稿保存不等于运行环境已更新，也不等于 Ozon 已可访问。**

用户需在此云环境的环境设置中审核、保存网络配置，并发布环境。只需 Ozon 公共域名访问，不需要店铺密码、Cookie、付费 API Key 或飞书 Webhook。若界面还需重连/重启，按平台提示操作。

配置生效后才做下一次请求，不在条件不变时重复尝试。剩余 P1 验证顺序：

1. 重试 robots.txt 并检查公开使用规则；若阻止该访问方式，停止相应采集路径。
2. 两家店各请求一次入口，记录重定向链、最终 URL 与页面内明确 seller ID；不从名字或 slug 推测 ID。
3. 对能正常访问的页面提取少量真实商品样本（每店最多 3～5 件），逐字段记录来源和缺失，不限定经营类目。
4. 只有出现公开分页证据且访问规则允许时，每店最多再请求一页；小样本只能验证分页行为，不能证明全店完整覆盖。数量、重复率、覆盖率及未请求页数分别记录。
5. 不在同一天试验后声称“每日稳定”。通过跨日少量重复验证 ID 和同口径价格，并保留首次观测时间；真实上架日期没有来源证据始终为未知。
6. 如遇平台 403、验证码或访问控制，停止该路径，明确记录平台级限制，不绕过，不误报为空店或商品下架。

本轮唯一外部前置条件是环境网络配置生效；没有新增付费或账号要求。后续仍仅测试这两家，未经真实数据验证不扩展至 15 家。
